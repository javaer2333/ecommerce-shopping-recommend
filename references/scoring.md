# 评分、过滤与报告口径

## 1. 数据 Schema

`products.json` 的最小结构如下。字段缺失写 `null`，不要填 0；数值型字段不要带单位。


字段说明：
- `sales_num`：解析后的数值，用于排序和评分；`sales` 保留平台原文。
- `positive_rate`：百分数数值，如 `98.2` 表示 98.2%。
- `nutrition`：数组，元素 `{"item": "能量", "per_100g": "180kJ", "nrv": "2%"}`；非食品为 `null`。
- `scores`：可省略，由脚本按第 3 节公式补算；有则优先用报告作者填的值。
- `evidence`：至少覆盖价格、好评率、销量三项。

## 2. 硬过滤

| 规则 | 默认阈值 | 例外 |
| --- | --- | --- |
| 好评率 | <95% 淘汰；食品/母婴/美妆 <96% | 平台不展示时用评分+差评推算，标「推算」；不得因缺失直接淘汰 |
| 评价量 | 评价 <30 且 销量 <100 | 品牌官方新品、预售可保留并注明 |
| 店铺评分 | 淘宝 <4.6；京东商品 <4.5；抖音口碑分 <4.6 | 自营/旗舰可看品牌整体，但仍需标注 |
| 闲鱼信用 | 芝麻信用 <650；或无实人认证且历史差评多 | 同城面交+验货宝可个案评估，需说明 |
| 价格异常 | 低于同类中位数 50% 且非官方/自营 | 清仓、临期需明示 |
| 三无食品 | 无 SC/生产商/生产日期 | 进口食品看中文标签与报关信息 |
| 差评集中 | 假货/过期/临期/翻新/货不对板 ≥3 条 | 记录关键词与链接 |

过滤顺序：先剔除三无/假货风险，再评好评率，再看销量与店铺，最后看价格异常。被排除项写入 `excluded`，保留名称、平台、原因，便于用户复核。

## 3. 评分公式

所有子分先归一化到 0–100，再加权。

### 3.1 口碑质量（35%）

```text
pr_score   = clamp((positive_rate - 90) × 10, 0, 100)      # 95→50, 97→70, 98→80, 99→90
rate_score = clamp((rating - 4.0) ÷ 0.9 × 100, 0, 100)      # 4.8→89, 4.9→100
conf_score = clamp(log10(review_count + 1) ÷ 5 × 100, 0, 100)  # 1千→60, 1万→80, 10万→100

quality = 0.70 × pr_score + 0.20 × rate_score + 0.10 × conf_score
```

- 无好评率：`quality = 0.65 × rate_score + 0.35 × conf_score`，标注「推算」。
- 无评分：用好评率与评价量，`quality = 0.8 × pr_score + 0.2 × conf_score`。

### 3.2 销量热度（20%）

```text
sales_score = clamp(log10(sales_num + 1) ÷ 5 × 100, 0, 100)
```

100→40，1,000→60，10,000→80，100,000→100。小众类目（乐器、专业设备）整体偏低是正常的，报告里说明「类目销量基线低」，不要为了分数硬抬。

### 3.3 价格竞争力（20%）

先算同款/同类的中位到手价（同规格、同新旧），再算单位价格。

```text
ratio = price ÷ median_price

ratio ≤ 1: price_score = 100 - 15 × (1 - ratio)        # 0.8→97, 0.5→92.5
ratio > 1: price_score = 100 - 55 × ln(ratio)          # 1.2→90, 1.5→77.7, 2→61.9
price_score = clamp(price_score, 0, 100)
```

- 食品/日化优先用 `元/100g` 或 `元/100mL` 算 ratio。
- 价格最低不等于最好：低于中位数 50% 先过「价格异常」硬过滤，再评分。
- 会员价、券后价、含税价必须同口径；不同口径不能放同一组算中位数。

### 3.4 店铺/品牌信任（15%）

| 类型 | 基础分 |
| --- | --- |
| 京东自营、天猫旗舰、品牌官方旗舰、百亿补贴品牌 | 90 |
| 京东 POP 高分店、天猫专营、抖音品牌旗舰 | 80 |
| 普通企业店、品牌授权店 | 70 |
| 个人店 | 55 |
| 闲鱼卖家 | 60 起，按下表调整 |

闲鱼调整：芝麻信用 ≥750 `+20`；700–749 `+12`；650–699 `+5`；<650 `-20`；实人认证 `+5`；支持验货宝 `+5`；历史差评多 `-10`。

店铺评分调整：`(shop_rating - 4.6) × 20`，限制在 `-10 ~ +10`。最终 clamp 到 0–100。

### 3.5 信息完整度（10%）

必填项按商品类型取：

- 通用：详情、规格、售后、来源链接、采集时间、图片（可选）
- 食品：通用 + 营养成分表 + 配料表 + 保质期

```text
info_score = clamp(40 + 60 × 已填项 ÷ 必填项, 40, 100)
```

### 3.6 风险扣分（0–15）

```text
risk_penalty = min(15,
    3 × len(risk_tags)
  + 2 × 严重差评关键词数        # 假货、过期、临期、翻新、货不对板、异味、过敏
  + 3 × 关键字段缺失数          # 价格、好评率、销量
)
```

### 3.7 总分与 AI 推荐率

```text
total = 0.35×quality + 0.20×sales + 0.20×price + 0.15×trust + 0.10×info
ai_rate = clamp(round(total - risk_penalty), 0, 100)
```

| AI 推荐率 | 档位 | 含义 |
| --- | --- | --- |
| ≥90 | 强烈推荐 | 口碑、销量、价格、信任都在线，风险低 |
| 80–89 | 推荐 | 综合优秀，允许 1 个明显短板 |
| 70–79 | 可考虑 | 有短板或数据不全，适合特定需求 |
| 60–69 | 谨慎 | 明显风险或口碑一般，仅预算极紧时考虑 |
| <60 | 不推荐 | 不进入推荐位，写入排除或对比说明 |

`AI 推荐率` 是模型综合分，不是平台官方指标，也不是概率。报告中首次出现时要解释一句。

## 4. 去重与同款对齐

- 分组键：`品牌 | 型号 | 规格/容量 | 版本（国行/海外/翻新）| 新旧`。
- 同组保留综合分最高的一条为主条目，其余平台价格写进 `vs_peers` 或对比表。
- 规格不同不合并：大包装单价低是正常的，用单位价格比较。
- 标题相似但型号不同（如 XM4/XM5、Pro/Pro 2）不合并。
- 同款价差 >20%：核对含券、含税、运费、赠品、保修、是否二手/临期。

## 5. 排名与多样性

1. 按 `ai_rate` 降序，取前 3–5 个。
2. 同一平台最多 2 个；若前 3 全是同一平台，用下一平台 ≥75 分的最佳项替换第 3 个，并注明「为保证平台多样性」。
3. 尽量覆盖 2 个价格带（入门/主流/高端）；没有合适候选不硬凑。
4. 第 1 名给「综合首选」，另设「性价比」「品质/售后」「预算有限」场景建议。

## 6. 数据可信度分级

| 级别 | 来源 | 报告标注 |
| --- | --- | --- |
| A | 平台商品详情页直接展示 | 无需标注 |
| B | 列表页/搜索摘要 | 「列表页数据」 |
| C | 由评分、评价、销量推算 | 「推算」 |
| D | 站外搜索/二手信息 | 「非平台实时数据，仅供参考」 |

报告中至少 70% 的关键字段应为 A/B 级；C/D 级字段不能作为唯一推荐依据。

## 7. 报告口径

- 价格：写「采集时到手价」，注明是否含券、含税、含运费；不写「全网最低」。
- 好评率：区分「平台展示」与「推算」；推算要写依据。
- 销量：保留平台原文（月销/已售/已拼），不跨口径排名。
- 食品：营养表统一每 100g/100mL，另附每份；高钠/高糖给提示，不给医疗建议。
- AI 推荐率：写清是本模型评分；推荐说明要引用具体证据（好评率、评价量、价格、售后）。
- 时间：报告顶部写生成时间；每条证据写采集时间。
- 免责声明：价格、库存、活动会变；下单前以平台实时页面为准；报告不含推广返利。
